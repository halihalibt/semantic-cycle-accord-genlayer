# Verified onchain examples

These examples use the deployed Semantic Cycle Accord contract on Stable Studionet
61999. All listed transactions were independently checked against public RPC and
Explorer evidence: FINALIZED / MAJORITY_AGREE / SUCCESS. Browser actions were
performed by the user; receipt verification is a separate evidence source.

## Incompatible service format

Assessment #2 evaluates ring `4 → 6 → 5 → 4`. An SVG requirement conflicts with a
PNG-only offer. Labels are `FIT / FIT / NO_FIT`; the result is NOT_MATCHED with
`cycle_id=0`. No Cycle was generated by Assessment #2. A later, unrelated
Assessment #3 created the currently existing Cycle #2.

- [Negative assessment transaction](https://explorer-studio.genlayer.com/tx/0x0bb517817a4dd54ec6afb1b1d04223fb78804ed3f6e561f2ca65ca31d2b3234f)

transaction evidence, not from invented Assessment fields or a universal consensus rule.

## Independent verification

Open the [wallet-free demonstration](https://halihalibt.github.io/semantic-cycle-exchange/?w=1),
then inspect the records and transaction links. The application reads latest-final
state; separate reads do not constitute an atomic historical snapshot. RPC failure
must not be interpreted as a fresh successful observation.

The [complete historical evidence index](PHASE_4C_E2E_EVIDENCE_INDEX.md) retains all
11 transactions, decoded arguments, signatures, repeated state reads and checksums.
Its final-state file describes the original verification window, including the
then-absent Cycle #2; it is not a claim that later records do not exist.
Original screenshot filename/hash metadata is retained there, but public image
bytes are unavailable. Intermediate screenshot observations are user-provided;
they do not substitute for an independently recovered historical RPC read.

Additional application cases and 17 independently checked receipts are in the
[application evidence index](https://github.com/halihalibt/semantic-cycle-exchange/blob/main/docs/FINAL_ONCHAIN_EVIDENCE_INDEX.md).
